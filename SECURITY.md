# Security policy

This is a reference implementation, not a security certification. Before public deployment, complete the checklist in docs/operations.md.

Do not post exploitable vulnerabilities, credentials or customer data in public issues. Enable GitHub private vulnerability reporting in your repository settings and use that channel. If it is unavailable, contact the repository owner privately.

Include affected versions, a minimal reproduction, expected impact and any proposed fix. Use synthetic data. Do not test against systems without permission.

Only the current main branch is maintained until a versioned support policy is published.
